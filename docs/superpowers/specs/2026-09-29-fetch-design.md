# Per-Exercise Fetch Tool — Design

Date: 2026-09-29
Status: approved in chat (§1-§3)

## 1. Goal
Let a beginner download one exercise standalone without cloning all 100.
`go run ./tools/fetch 01_syntax` produces a folder that passes `go vet`
and runs `go test` out of the box (failing test until solved, same as monorepo).

## 2. Non-goals
- No full-course starter zip, no progress tracking, no solution injection.
- No new test deps, no change to `exercises/` layout or `learngo` module.
- No book-site download button in v1 (tool first, site can link it later).

## 3. Architecture / CLI (§1 approved)
New tool `tools/fetch/main.go`, stdlib only, same style as `tools/bookgen/main.go`.

```
go run ./tools/fetch <query> [--out DIR] [--branch main|solutions] [--remote|--local] [--list] [--force]
```

- `<query>`: `01_syntax`, `syntax`, or `01_intro/01_syntax` (substring, case-insensitive).
- `--out`: default `./<exercise-name>` (e.g. `./01_syntax`).
- `--branch`: default `main`; `solutions` fetches solved files, same paths.
- Mode auto-detect: if `./exercises` exists use local copy, else remote.
  `--local` / `--remote` override.
- `--list`: print `section/name` lines from manifest, exit 0.
- Output dir contents: `README.md` + `<stub>.go` + `<stub>_test.go` + generated `go.mod`:
  `module fetch/<name>` + `go 1.23`. No `learngo/` imports exist (verified:
  `exercises/01_intro/01_syntax` is self-contained), so standalone `go test` works.

## 4. Data flow (§2 approved)
- Commit `tools/fetch/manifest.json`: `[{section, name, files:[README, stub, test]}]`,
  generated by scanning `exercises/*/*/README.md` (same walk as bookgen).
- Local mode: resolve query via manifest -> copy 3 files -> write `go.mod`.
- Remote mode: resolve via local manifest if present, else fetch
  `raw.githubusercontent.com/hamzahraihan/100-exercises-to-learn-go/<branch>/tools/fetch/manifest.json`,
  then GET 3x:
  `.../<branch>/exercises/<section>/<name>/<file>`.
- Refuse to write into non-empty `--out` unless `--force`.
- Ambiguous query (2+ matches) prints candidates, exit 1.

## 5. Errors / testing / docs (§3 approved)
- Errors to stderr as `fetch: <what> + fix`, exit non-zero:
  unknown exercise -> list close matches; network fail -> print URL+branch;
  dirty out dir -> suggest `--force`.
- Tests `tools/fetch/main_test.go`, stdlib only, no network:
  resolve exact/substring/ambiguous, `go.mod` inject content,
  local copy via `t.TempDir()`, remote via `httptest.Server`.
- Docs: README gets `Fetch one exercise` section with `--list` + single-fetch
  example. CI unchanged (`go vet ./...`, `go build ./...` must pass).

## 6. Risks
- Manifest drift: mitigate by generating in CI check or documenting
  `go run ./tools/fetch --dump-manifest` regeneration step before commit.
- Single-file exercises assumed: tool copies exactly the 3 listed files;
  if a future exercise adds a helper file, manifest `files[]` covers it.
